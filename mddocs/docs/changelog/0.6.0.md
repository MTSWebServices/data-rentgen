# 0.6.0 (2026-07-23) { #0.6.0 }

## Breaking Changes

- Now Data.Rentgen reads configuration from `config.yml` file, which has higher priority than environment variables. ([#505](https://github.com/MTSWebServices/data-rentgen/issues/505))
- Replace `logging: preset: colored|plain|json` with a format used by `logging.dictConfig()`.

## Consumer

- Improve dataset symlink resolution by using recursion. ([#476](https://github.com/MTSWebServices/data-rentgen/issues/476))

- If Data.Rentgen receives RunEvent with Spark job with `name=unknown`, it should have no parent job, no tags and no dependencies. ([#480](https://github.com/MTSWebServices/data-rentgen/issues/480))

    Otherwise multiple workers will update the same row each time, although it is temporary.
    Workaround for [OpenLineage #3846](https://github.com/OpenLineage/OpenLineage/issues/3846).

- Updated existing job dependencies when a non null dependency type was received. ([#490](https://github.com/MTSWebServices/data-rentgen/issues/490))

- Drop database name from datasets for ClickHouse & MySQL ([#463](https://github.com/MTSWebServices/data-rentgen/issues/463))

- Ignore datasets with reserved names like `information_schema.tables`, `all_tables`, `dual` and so on. ([#483](https://github.com/MTSWebServices/data-rentgen/issues/483))

- Fixed workaround for [OpenLineage issue #3846](https://github.com/OpenLineage/OpenLineage/issues/3846) -
  previously DataRentgen may merge different jobs into one if they were a parent of Spark `unknown` app job. ([#473](https://github.com/MTSWebServices/data-rentgen/issues/473))

- Properly update `job_id` / `run_id` identifiers if operation bound to job/run was changed. ([#475](https://github.com/MTSWebServices/data-rentgen/issues/475))

- Fix error while fetching for `Tag.name` or `TagValue.value` being case-sensitive when insert is case-insensitive. ([#485](https://github.com/MTSWebServices/data-rentgen/issues/485))

## REST API

- Relax filters on ``GET /v1/runs`` endpoint - ``since`` is not mandatory anymore. ([#495](https://github.com/MTSWebServices/data-rentgen/issues/495))
- Allow passing `run_id` filter to `GET /v1/operations` endpoint without `since` filter. ([#496](https://github.com/MTSWebServices/data-rentgen/issues/496))
- Improve query plan for bulk queries by preferring index scan. ([#497](https://github.com/MTSWebServices/data-rentgen/issues/497))
- Improve query plan for queries with `id` filter. ([#499](https://github.com/MTSWebServices/data-rentgen/issues/499))
- Simplify execution plan for SQL queries used for fetching aggregated input/outputs. ([#500](https://github.com/MTSWebServices/data-rentgen/issues/500))
- Reduce number of database requests emitted by ``GET /v1/lineage`` endpoints. ([#503](https://github.com/MTSWebServices/data-rentgen/issues/503))

## UI

- Allow to pass empty `since` in runs list.
- Add more icons for databases & ETL tools supported by OpenLineage.
- Switch Docker image from `nginx:alpine` to `nginx:debian`.

## Database

- Fix `data_rentgen.db.scripts.cleanup_partitions` script ignored detached partitions while dropping old partitions. ([#449](https://github.com/MTSWebServices/data-rentgen/issues/449))
- Add foreign key constraints on columns `job_id`, `dataset_id`, `schema_id`, `sql_query_id` to partitioned tables (`run`, `operation`, `input`, `output`, `column_lineage`). ([#484](https://github.com/MTSWebServices/data-rentgen/issues/484))
- Reduced `job_dependency` storage size and consumer database load by using `(from_job_id, to_job_id)` as the primary key and inserting dependencies in bulk. ([#489](https://github.com/MTSWebServices/data-rentgen/issues/489))
- Improve SQL queries for fetching job/run ancestors or descendants - previously it contained cartesial join. ([#492](https://github.com/MTSWebServices/data-rentgen/issues/492))
- Reduced `dataset_column_relation` storage size and column lineage query time by using `(fingerprint, source_column, target_column)` as the primary key. ([#493](https://github.com/MTSWebServices/data-rentgen/issues/493))
- Add lightweight ``BRIN`` index over ``run.started_at`` and ``run.ended_at`` columns. ([#494](https://github.com/MTSWebServices/data-rentgen/issues/494))

## Monitoring

Added Prometheus metrics middleware to Kafka consumer, exposed via `GET /monitoring/metrics` endpoint. ([#501](https://github.com/MTSWebServices/data-rentgen/issues/501))

This allows tracking message processing errors caused by database conflicts, deadlocks or unavailability.

## Documentation

Switched from Sphinx to Mkdocs. ([#482](https://github.com/MTSWebServices/data-rentgen/issues/482))
